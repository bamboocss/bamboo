### Update package.json scripts

Add `"prepare": "bamboo codegen"` to `scripts`. It runs [codegen](/docs/references/cli#codegen) after every dependency
install, so the output directory can stay in `.gitignore`.

### Configure the content

Make sure that all of the paths of your React components are included in the `include` section of the `bamboo.config.ts`
file.

```js {8} filename="bamboo.config.ts"
import { defineConfig } from '@bamboocss/dev'

export default defineConfig({
  // Whether to use css reset
  preflight: true,

  // Where to look for your css declarations
  include: ['./src/**/*.{js,jsx,ts,tsx}', './pages/**/*.{js,jsx,ts,tsx}'],

  // Files to exclude
  exclude: [],

  // The output directory for your css system
  outdir: 'styled-system',
})
```

### Add the plugin to your Vite config

```ts filename="vite.config.ts"
import { defineConfig } from 'vite'
import bamboocss from '@bamboocss/vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [bamboocss(), react()],
})
```

### Import the virtual stylesheet

```ts filename="src/main.tsx"
import 'virtual:bamboo.css'
```

Reference the ambient declaration so TypeScript accepts that import:

```ts filename="src/vite-env.d.ts"
/// <reference types="vite/client" />
/// <reference types="@bamboocss/vite/client" />
```

That is the whole setup – no `postcss.config.cjs` entry for Bamboo, and no file carrying the `@layer` statement, since
the virtual module emits its own. You still need PostCSS for anything else you run through it, autoprefixer included.

In development the stylesheet is served from memory and hot-replaced in place, so editing a style repaints without a
reload or a loss of component state. In a production build it is hashed into the asset graph like any other CSS.

> **Note:** Feel free to remove `src/App.css` file as we don't need it anymore, and make sure to remove the import from
> the `src/App.tsx` file.

## Start your build process

Start the dev server with `pnpm dev`.

### Start using Bamboo

```tsx filename="src/App.tsx"
import { css } from '../styled-system/css'

function App() {
  return <div className={css({ fontSize: '2xl', fontWeight: 'bold' })}>Hello 🎋!</div>
}

export default App
```

## Plugin options

`bamboocss()` compiles Bamboo style calls in development and production, and emits their globally shared declaration
atoms through the virtual stylesheet:

```tsx
// you write
export const title = css({ fontSize: 'lg', fontWeight: 'bold' })

// the bundle gets
export const title = '_4p9d _7bc2'
```

| option            | default | what it does                                                     |
| ----------------- | ------- | ---------------------------------------------------------------- |
| `maxRecipeStates` | `65536` | Bound exact build-time enumeration for runtime recipe axes.      |
| `reportSummary`   | `true`  | Print a compiler coverage summary when a build finishes.         |
| `reportSkipped`   | `false` | Report every call site the compiler rejected, and why, per file. |
| `configPath`      | –       | Path to `bamboo.config.ts`, resolved the same way as the CLI.    |
| `cwd`             | –       | Directory the config is resolved from.                           |

Compilation and strict rejection are not options. A style-producing call that cannot be represented by the emitted CSS
fails instead of retaining a runtime fallback. See [Source compilation](/docs/guides/source-transformation) for the
accepted static and finite-dynamic shapes.

## Alternative: emit CSS from PostCSS

Bamboo can emit the stylesheet through PostCSS instead of the Vite plugin. Install `@bamboocss/dev` alone, run
`bamboo init --postcss` to write `postcss.config.cjs`, and add an entry CSS file carrying the layer order:

```css filename="src/index.css"
@layer reset, base, tokens, recipes, utilities;
```

Import that file from your root component in place of `virtual:bamboo.css`. This is a different integration: it has no
source compiler, so `css()` calls resolve at runtime and recipes retain their named extraction representation.

<Callout type="warning">
  Use this **or** `@bamboocss/vite`, not both. Each emits a complete stylesheet, so configuring the two together puts
  two copies of it in your bundle – and a minifier merges most of the duplication away, which makes it read as a
  rounding error rather than as the whole sheet twice.
</Callout>

## Troubleshooting

If your IDE does not autocomplete `styled-system` imports, add that directory to `include` in `tsconfig.json`. See
[the CLI guide](/docs/installation/cli#troubleshooting).
