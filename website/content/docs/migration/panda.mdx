---
title: Migrating from Panda CSS
description: Migrate your project from Panda CSS to Bamboo CSS.
---

Bamboo CSS started as a fork of [Panda CSS](https://panda-css.com/), so unlike the other guides in this section this one
is not a rewrite. The styling API is the same: your style objects, recipes, patterns, conditions and tokens carry over
unchanged. What changes is the name of the package they come from.

For most projects this is a find-and-replace of `panda` with `bamboo`, plus a re-run of codegen.

## What stays the same

- `css`, `cva`, `sva`, `cx`, the pattern functions and the JSX factory – same names, same signatures. `cx` resolves
  conflicts rather than concatenating, which is a behaviour change; see [below](#cx-resolves-conflicts).
- Recipes, slot recipes, variants, compound variants and default variants.
- Tokens, semantic tokens, conditions, breakpoints, themes, `staticCss`, cascade layers.
- The config shape, with one exception. Every key you have in `panda.config.ts` is valid in `bamboo.config.ts` except
  `studio`, which has no equivalent – delete it.
- The output directory. It still defaults to `styled-system`, so imports like `styled-system/css` do not move.

Because the generated output directory keeps its name and shape, the only imports you have to touch are the ones that
name the tool itself – the config file, the PostCSS plugin, and any direct `@pandacss/*` imports.

## Rename the packages

Every package moves from the `@pandacss` scope to `@bamboocss`. The ones a project normally depends on:

| Panda CSS                | Bamboo CSS                 |
| ------------------------ | -------------------------- |
| `@pandacss/dev`          | `@bamboocss/dev`           |
| `@pandacss/types`        | `@bamboocss/types`         |
| `@pandacss/preset-base`  | `@bamboocss/preset-base`   |
| `@pandacss/preset-panda` | `@bamboocss/preset-bamboo` |
| `@pandacss/postcss`      | `@bamboocss/postcss`       |

The internal packages (`@pandacss/core`, `/node`, `/parser`, `/generator`, `/token-dictionary` and the rest) follow the
same rule if you import them directly.

<Callout type="info">
  The default preset is the one rename that is not a straight scope swap: `@pandacss/preset-panda` becomes
  `@bamboocss/preset-bamboo`. If you never listed presets explicitly, the defaults are applied for you and there is
  nothing to change.
</Callout>

## Step by step

<Steps>

  </Tab>
  {/* <!-- prettier-ignore-end --> */}

### Rename the config file

`panda.config.ts` becomes `bamboo.config.ts`. Bamboo looks for `bamboo.config.{ts,js,mts,mjs}` and will not pick up a
file under the old name.

Update the import inside it, and the preset names if you listed them:

```ts
// bamboo.config.ts
import { defineConfig } from '@bamboocss/dev'

export default defineConfig({
  presets: ['@bamboocss/preset-base', '@bamboocss/preset-bamboo'],
  include: ['./src/**/*.{js,jsx,ts,tsx}'],
  outdir: 'styled-system',
})
```

### Update the PostCSS config

```js
// postcss.config.cjs
module.exports = {
  plugins: {
    '@bamboocss/dev/postcss': {},
  },
}
```

### Update your scripts

The CLI is `bamboo` (`bamboocss` also works). Every command keeps its name, so `panda codegen` becomes `bamboo codegen`,
`panda cssgen` becomes `bamboo cssgen`, and so on.

```json
{
  "scripts": {
    "prepare": "bamboo codegen"
  }
}
```

### Regenerate the output directory

Delete the existing `styled-system` directory and generate it again, so nothing from the previous install is left
behind:

```bash
rm -rf styled-system
pnpm bamboo codegen
```

</Steps>

## `cx` joins, in both tools

Panda's `cx` joins classnames and so does Bamboo's, so this needs no migration. Two atomic classes for the same property
both end up on the element and the browser picks by stylesheet order.

What differs is the advice about what to do instead. A **config recipe** — one declared in `theme.recipes` — lands in
the `recipes` layer, so a consumer's `css()` in `utilities` overrides it deterministically. An inline `cva()` does not:
its output is atomic, exactly like `css()`, and sits in the same layer as the consumer. See
[Merging styles](/docs/concepts/merging-styles).

## Things that are easy to miss

- **`PANDA_DEBUG`** is now `BAMBOO_DEBUG`. See [Debugging](/docs/guides/debugging).
- **There is no JSX factory.** `styled.div`, `panda.div`, `styled('button', recipe)`, `createStyleContext` and
  `splitCssProps` have no equivalent, and `styled-system/jsx` is not generated at all. Style props become a `css()`
  call, and a recipe component becomes an ordinary component that calls the recipe:

  ```tsx
  // panda
  const Button = styled('button', buttonRecipe)
  <Button size="sm" />

  // bamboo
  const Button = (props: ButtonProps) => {
    const [variantProps, rest] = buttonRecipe.splitVariantProps(props)
    return <button {...rest} className={cx(buttonRecipe(variantProps), props.className)} />
  }
  ```

  `jsxFramework`, `jsxFactory` and `jsxStyleProps` are gone from the config with it — delete them.

- **The ESLint plugin** is `@bamboocss/eslint-plugin`.
- **Editor and CI caches.** The TypeScript server holds on to the old `styled-system` types; restart it after
  regenerating.
- **`.gitignore`.** If you generate `styled-system` in CI rather than committing it, the entry does not change, since
  the directory name is the same.

## Worth a look once you have migrated

These are documented in full elsewhere, and none of them are required to get a migrated project building:

- [Source transformation](/docs/guides/source-transformation) – `@bamboocss/vite` folds statically-resolvable `css()`
  and pattern calls into plain class strings at build time, so they cost nothing at runtime.
- [`pruneUnusedTokens`](/docs/references/config#pruneunusedtokens) – drops token CSS variables nothing can reach, which
  is usually the largest single saving in render-blocking CSS.
- [Spec files](/docs/theming/spec) – generate a machine-readable description of your design system.
- [MCP server](/docs/ai/mcp-server) and [llms.txt](/docs/ai/llms-txt) – expose your design system to AI tooling.

## Getting help

If something does not carry over, check the [open issues](https://github.com/bamboocss/bamboo/issues) first. If you
cannot find it, please open [a new issue](https://github.com/bamboocss/bamboo/issues/new/choose) with a minimal
reproduction.
