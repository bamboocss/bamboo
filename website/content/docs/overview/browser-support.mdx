title: Browser Support

Bamboo CSS is built with modern CSS features and uses [PostCSS](https://postcss.org/) to add support for older browsers.
Bamboo supports the latest, stable releases of major browsers that support the following features:

- [CSS Variables](https://caniuse.com/css-variables)
- [CSS Cascade Layers](https://caniuse.com/css-cascade-layers)
- Modern selectors, such as [`:where()`](https://caniuse.com/mdn-css_selectors_where) and
  [`:is()`](https://caniuse.com/css-matches-pseudo)

One further feature, [`@scope`](https://caniuse.com/css-cascade-scope), is used only by projects that write slot recipes
a particular way. It raises the floor when it applies — see [Slot recipes and `@scope`](#slot-recipes-and-scope) — and
is not emitted at all otherwise.

## Browserlist

Based on the above criteria, the following browsers are supported:

```txt
>= 1%

not dead
Chrome >= 99
Edge >= 99
Firefox >= 97
iOS >= 15.4
Safari >= 15.4
Android >= 115
Opera >= 73
```

## Slot recipes and `@scope`

A [slot recipe](/docs/concepts/slot-recipes) that declares a slot named `root` emits its non-root slots' variant styles
inside an `@scope` rule, so that no slot has to be handed the variant at runtime:

```css
@scope (.checkbox__root--size_md) to (.checkbox__root) {
  .checkbox__control {
    width: 10;
  }
}
```

That is the only place Bamboo emits `@scope`. A project with no slot recipes, or whose slot recipes declare no `root`
slot, never produces one and keeps the baseline above.

Where it does apply, the floor rises to:

```txt
Chrome >= 118
Edge >= 118
Firefox >= 128
iOS >= 17.4
Safari >= 17.4
Android >= 118
Opera >= 104
```

There is no polyfill. `@scope` decides between two matching rules by DOM proximity, which a build step cannot compute
and a stylesheet cannot express — the whole point is that the nearest root wins over an outer one. Anything claiming to
polyfill it either ignores nesting or needs a runtime.

If you need to support browsers below that line, set `scopeRoots: []` on the slot recipe. Bamboo then has no anchor to
scope by, so it falls back to a variant class per slot and emits no `@scope` — every slot stays callable, and the
variant is delivered through the class as before.

```ts
defineSlotRecipe({
  className: 'checkbox',
  slots: ['root', 'control', 'label'],
  scopeRoots: [], // no @scope; every slot carries its own variant class
  variants: { size: { md: { control: { width: '10' } } } },
})
```

Renaming a slot to avoid the scoping default also works, since the anchor defaults to a slot called `root` — but a
slot's name is part of your component's public API, and changing it to dodge a browser constraint is the worse of the
two.

## Polyfills

In event that you need to support older browsers, you can use the following polyfills in your PostCSS config:

- [autoprefixer](https://github.com/postcss/autoprefixer): Adds vendor prefixes to CSS rules using values from
  [Can I Use](https://caniuse.com/).
- [postcss-cascade-layers](https://www.npmjs.com/package/@csstools/postcss-cascade-layers): Adds support for CSS Cascade
  Layers.

There is deliberately none listed for `@scope`; see above for why, and for the way out.

Here is an example of a `postcss.config.js` file that uses these polyfills:

```js
module.exports = {
  plugins: ['@bamboocss/dev/postcss', 'autoprefixer', '@csstools/postcss-cascade-layers'],
}
```
