Bamboo scans your JavaScript and TypeScript for style props and function calls, and generates atomic CSS for the call
sites it finds. It runs as a CLI or a PostCSS plugin.

You author styles as plain objects. Tokens, recipes and variants are generated from your config as types, so the editor
autocompletes them and the compiler checks them.

## How is this different from Panda CSS?

Bamboo CSS is a fork of [Panda CSS](https://panda-css.com/) v1. `css`, `cva`, `sva`, `cx`, the pattern functions,
recipes and the config shape all carry over, so [migrating](/docs/migration/panda) is largely a rename — but the API is
smaller (no JSX factory, no template literals) and a few things behave differently. See
[why we forked](/docs/overview/why-bamboo#why-we-forked-panda-css) and
[what changed](/docs/overview/faq#how-is-bamboo-css-different-from-panda-css).

## Features

- ⚡️ Write plain style objects, extracted at build time
- 🪶 [Optional zero runtime](/docs/guides/source-transformation) – fold static `css()`, pattern and recipe calls into
  plain class strings at build time
- ✨ Modern CSS output – cascade layers `@layer`, css variables and more
- ✂️ Prune [unused tokens](/docs/references/config#pruneunusedtokens) and
  [keyframes](/docs/references/config#pruneunusedkeyframes) – ship only what your app uses
- 📦 [Grouped class output](/docs/references/config#cssmode) – one class per `css()` call instead of one per property
- 🎯 [Predictable overrides](/docs/concepts/cascade-layers) – a recipe's styles sit in a lower cascade layer than
  `css()`, so a consumer's override wins by origin rather than by source order
- 🛟 [Fallback values](/docs/concepts/writing-styles#fallback-values) – `fallback(100dvh, 100vh)` for progressive
  enhancement, in one declaration
- 🎬 [View transitions](/docs/concepts/view-transitions) – `viewTransition()` writes the `::view-transition-*` rules and
  hands back one class to share across elements
- 🦄 Works with most JavaScript frameworks
- 🚀 [Recipes and Variants](/docs/concepts/recipes) – composable style variants, an API inspired by Stitches
- 🎨 High-level design tokens support for simultaneous themes
- 💪 Type-safe styles and autocomplete (via codegen)
- 🤖 [MCP server](/docs/ai/mcp-server) – let AI assistants read your tokens, recipes and usage

## Cheat Sheet

Everything below is a function call that returns a class string. There is no JSX factory and no template literal syntax
— one way to write a style, which is also what lets the [build-time fold](/docs/guides/source-transformation) resolve so
much of it.

### Styling

```jsx
import { css, cx } from '../styled-system/css'

css({ color: 'red.500', padding: '4' }) // tokens by name
css({ color: '#f00', padding: '13px' }) // raw values work too
css({ display: '[var(--btn-display)]' }) // escape hatch — skips token checking

css({ _hover: { color: 'red.700' } }) // condition as a block
css({ color: { base: 'red.500', _hover: 'red.700' } }) // …or per property
css({ fontSize: { base: 'sm', md: 'lg' } }) // responsive, mobile first
css({ color: { base: 'black', _dark: 'white' } }) // theming condition

cx('a', cond && 'b') // joins class names, never merges
```

### Composing styles

`cx` concatenates — it does not resolve conflicts. Merge the **objects** instead, where the last write wins per
property:

```jsx
css({ padding: '4' }, { padding: '8' }) // → padding 8
css(base, props.css) // the overridable-component idiom
css.raw({ padding: '4' }) // a style object to merge later
```

See [Merging styles](/docs/concepts/merging-styles).

### Recipes

```jsx
import { cva, sva } from '../styled-system/css'

const button = cva({
  className: 'button', // optional; hashed from the config if omitted
  base: { borderRadius: 'md' },
  variants: { size: { sm: { padding: '2' }, lg: { padding: '4' } } },
  defaultVariants: { size: 'sm' },
  compoundVariants: [{ size: 'lg', tone: 'brand', css: { fontWeight: 'bold' } }],
})

button({ size: 'lg' }) // 'button button--size_lg'
button.raw({ size: 'lg' }) // the style object instead
const [variantProps, rest] = button.splitVariantProps(props)
```

A recipe's classes land in the `recipes` [cascade layer](/docs/concepts/cascade-layers), so a consumer's `css()` in
`utilities` overrides them by layer rather than by source order. Declaring the same shape in `theme.recipes` generates
only the variants you use — see
[atomic vs config recipes](/docs/concepts/recipes#should-i-use-atomic-or-config-recipes-).

`sva` is the same for multi-part components, and its variants are [scoped](/docs/concepts/slot-recipes#variant-scoping)
so only the enclosing slot takes props:

```jsx
const checkbox = sva({ className: 'checkbox', slots: ['root', 'control'] /* … */ })
checkbox({ size: 'md' }).root // 'checkbox__root checkbox__root--size_md'
checkbox({ size: 'md' }).control // 'checkbox__control' — a constant
```

### Patterns

Layout helpers that are `css()` with a transform applied. `stack`, `hstack`, `vstack`, `box`, `flex`, `grid`,
`gridItem`, `center`, `circle`, `square`, `container`, `wrap`, `spacer`, `divider`, `float`, `aspectRatio`, `bleed`,
`cq`, `linkOverlay`, `visuallyHidden`.

```jsx
import { stack } from '../styled-system/patterns'
;<div className={stack({ gap: '4', align: 'center' })} />
```

### Tokens and escape hatches

```jsx
import { token } from '../styled-system/tokens'
import { css, fallback, viewTransition } from '../styled-system/css'

token('colors.red.500') // the resolved value
token.var('colors.red.500') // var(--colors-red-500)
css({ height: fallback('100dvh', '100vh') }) // progressive enhancement
viewTransition({
  /* … */
}) // ::view-transition-* rules, one class
```

See [Writing styles](/docs/concepts/writing-styles) for the full surface.
