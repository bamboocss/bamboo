Everything below is a function call that returns a class string. There is no JSX factory and no template literal syntax
— one way to write a style, which is also what lets the [build-time fold](/docs/guides/source-transformation) resolve so
much of it.

## Styling

```jsx
import { css, cx } from '../styled-system/css'

css({ color: 'red.500', padding: '4' }) // tokens by name
css({ color: '#f00', padding: '13px' }) // raw values work too
css({ display: '[var(--btn-display)]' }) // escape hatch — skips token checking

css({ _hover: { color: 'red.700' } }) // condition as a block
css({ color: { base: 'red.500', _hover: 'red.700' } }) // …or per property
css({ fontSize: { base: 'sm', md: 'lg' } }) // responsive, mobile first
css({ color: { base: 'black', _dark: 'white' } }) // theming condition

cx('a', cond && 'b') // joins class names, never merges
```

## Composing styles

`cx` concatenates — it does not resolve conflicts. Merge the **objects** instead, where the last write wins per
property:

```jsx
css({ padding: '4' }, { padding: '8' }) // → padding 8
css(base, props.css) // the overridable-component idiom
css.raw({ padding: '4' }) // a style object to merge later
```

See [Merging styles](/docs/concepts/merging-styles).

## Recipes

```jsx
import { cva, sva } from '../styled-system/css'

const button = cva({
  className: 'button', // optional; hashed from the config if omitted
  base: { borderRadius: 'md' },
  variants: { size: { sm: { padding: '2' }, lg: { padding: '4' } } },
  defaultVariants: { size: 'sm' },
  compoundVariants: [{ size: 'lg', tone: 'brand', css: { fontWeight: 'bold' } }],
})

button({ size: 'lg' }) // 'button button--size_lg'
button.raw({ size: 'lg' }) // the style object instead
const [variantProps, rest] = button.splitVariantProps(props)
```

A recipe's classes land in the `recipes` [cascade layer](/docs/concepts/cascade-layers), so a consumer's `css()` in
`utilities` overrides them by layer rather than by source order. Declaring the same shape in `theme.recipes` generates
only the variants you use, apart from an axis passed dynamically — see
[inline vs config recipes](/docs/concepts/recipes#should-i-use-an-inline-or-config-recipe).

`sva` is the same for multi-part components, and its variants are [scoped](/docs/concepts/slot-recipes#variant-scoping)
so only the enclosing slot takes props:

```jsx
const checkbox = sva({ className: 'checkbox', slots: ['root', 'control'] /* … */ })
checkbox({ size: 'md' }).root // 'checkbox__root checkbox__root--size_md'
checkbox({ size: 'md' }).control // 'checkbox__control' — a constant
```

## Patterns

Layout helpers that are `css()` with a transform applied. `flex`, `grid`, `gridItem`, `center`, `container`, `spacer`,
`divider`, `float`, `aspectRatio`, `bleed`, `linkOverlay`.

```jsx
import { flex } from '../styled-system/patterns'
;<div className={flex({ direction: 'column', gap: '4', align: 'center' })} />
```

## Tokens and escape hatches

```jsx
import { token } from '../styled-system/tokens'
import { css, fallback, viewTransition } from '../styled-system/css'

token('colors.red.500') // var(--colors-red-500)
token.value('colors.red.500') // the resolved value, for canvas and the like
css({ height: fallback('100dvh', '100vh') }) // progressive enhancement
viewTransition({
  /* … */
}) // ::view-transition-* rules, one class
```

See [Writing styles](/docs/concepts/writing-styles) for the full surface.
